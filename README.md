# ЕдаДа · Когалым

Личное веб-приложение для меню по бюджету и КБЖУ. React 19 + Vinext, TypeScript, Cloudflare D1, Sites. Закрытый доступ через ChatGPT, данные сохраняются между устройствами.

## Возможности

- Бюджет всей покупки, минимум белка и допустимый процент недобора, максимум калорий/жиров/углеводов, 1–3 блюда, время приготовления и исключения продуктов.
- Покупка целых упаковок и минимальное число упаковок по акции; общий ингредиент используется несколькими блюдами. Стоимость съедаемого и сумма на кассе показаны отдельно.
- Пять сетей: Пятёрочка, Светофор, Магнит, Перекрёсток и Монетка. Используются только реальные цены; синтетический режим удалён.
- Каталог и этикетки, ручные цены и JSON/CSV импорт, очередь проверки собранных цен, история меню, рецепты с граммовками и выгрузка покупок.
- Firecrawl получает свежие страницы; Gemini 3.5 Flash-Lite извлекает данные, Gemini 3.8 Flash создаёт рецепты из известных продуктов. Ключи можно задать через интерфейс; в D1 они зашифрованы AES-GCM серверным мастер-ключом.
- Сохранённая библиотека Gemini пополняется из всего подходящего каталога: нет ограничения первыми 120 товарами. Состав и явные риски проверяются, стоимость и КБЖУ считаются по текущим предложениям. Неясная подготовка отправляется на уточнение. Лимит — 40 запросов в сутки; каждая попытка, включая резервную модель, учитывается до вызова API.
- «Проверка товаров»: задания по КБЖУ, массе и категории, источники и подтверждение этикетки, XP и уровни, пропуск и отмена. Ручные подтверждения защищены от автоматической перезаписи.
- Ручное, ежедневное или еженедельное обновление. Cloud-расписание вызывает защищённый writer и учитывает настройку частоты, даже когда приложение закрыто.

## Первый запуск пользователем

1. Войти в опубликованное приложение своим ChatGPT-аккаунтом.
2. В «Настройках» добавить ключ Google AI Studio и, для сбора сайтов, Firecrawl. Сохранить и проверить список моделей. Без ключей работают встроенные рецепты и расчёт по введённым ценам.
3. В каталоге проверить загруженные цены, ввести новые или импортировать прайс. Для новой записи подтвердить Когалым и условия; при необходимости заменить справочные КБЖУ этикеткой.
4. В «Магазинах» добавить прямые ссылки на локальные каталоги/товары и выполнить обновление. Проверить кандидаты в каталоге. Карточка без выбора нужного магазина не доказывает локальную цену.
5. Указать цели и собрать меню. При сохранённом ключе Gemini библиотека пополняется автоматически при подборе и фоновом обновлении. В панели библиотеки можно приостановить автоматику или создать дополнительный пакет. При временной недоступности основной модели используется настроенная Flash Lite, с часовым перерывом перед возвратом к основной.

## Локальная разработка

Node >=22.13 (для тестов рекомендуется Node24), npm. `npm ci`, затем `npm run dev`. Запуск на `127.0.0.1`. Портативный Sites starter симулирует локальный вход через `/signin-with-chatgpt?return_to=/`; это не попадает в production.

Для локальной базы сначала `npm run db:generate` при изменении схемы, затем build для Wrangler-конфига. Применить **только ещё не применённую** миграцию:

```powershell
npm run build
# Для новой пустой локальной базы — все миграции по порядку.
Get-ChildItem drizzle/000*.sql | Sort-Object Name | ForEach-Object {
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file $_.FullName
  if ($LASTEXITCODE -ne 0) { throw 'Не удалось применить миграцию' }
}
```

Локальные секреты в игнорируемом `.dev.vars`; ключи API необязательны. `APP_ENCRYPTION_KEY` — криптографически случайная hex-строка из 64 знаков. Никогда не менять production master без миграции уже зашифрованных API-ключей.

Проверки: `npm test`, `npm run typecheck`, `npm run build`. При работающем dev-сервере `npm run test:local` проверяет API, D1 readback, отклонение некорректных данных и шифрование; создаёт только явно тестовые локальные цены и удаляет их после проверки. Не направлять этот скрипт на production.

## Границы текущей версии

Каталог расширяется автоматически: городские цены сопоставляются с точными характеристиками товара из внешних источников. Неполные карточки сохраняются и попадают на дальнейшую проверку; демо-товары не используются. КБЖУ со справочника и с этикетки различаются, оценочный съедобный выход отмечается явно. Цена из городского каталога не доказывает остаток и цену на кассе конкретной точки. Исчезнувшие карточки получают неизвестное наличие, а не выдуманный остаток.

Рецепты Gemini сохраняются с моделью, временем и идентичностями ингредиентов. Изменения цены и КБЖУ пересчитывают меню; изменения товара, кулинарной роли или аллергенов требуют нового рецепта. Проверки JSON и текста выявляют конкретные ошибки, но не доказывают вкусовую или полную семантическую корректность рецепта. Неподтверждённая масса, сырой/готовый вид или непищевой товар требуют уточнения. Поиск меню ограничен вычислительным бюджетом и не доказывает глобальную оптимальность.

Рабочие каталоги, пользовательские данные, история, ключи и актуальная библиотека находятся в D1 опубликованного приложения и не входят в Git. Репозиторий содержит исходники, миграции и явно тестовые данные; клонирование не переносит production-базу. Обновление GitHub-копии само по себе не публикует Sites: публикация выполняется через управляемый source workflow. `.env.example` содержит только имена настроек; `.dev.vars`, `.env`, runtime state и зависимости игнорируются.
