# Автономное обновление ЕдаДа

Проект Sites: `appgprj_6ad6076d614c81918fb73eaf5c162c70`.
Ожидаемый origin: `https://eda-da-kogalym.social-grape-1472.chatgpt.site`.

Приложение приватное, принадлежит одному владельцу. Хостинг проверяет браузерную аутентификацию и служебный bypass до выполнения Worker. Не меняйте аудиторию на public без отдельной доработки серверной авторизации service endpoint.

Cloud-задача получает актуальные данные доступа только через `get_site` для этого проекта. Если ответ содержит `siwc_bypass_bearer_token`, использует его только для origin этого приложения в заголовке `OAI-Sites-Authorization: Bearer <token>`. Токен нельзя сохранять в файлы, промпт или вывод. Сервисный токен не является пользовательской идентичностью.

Writer: `POST /api/refresh-service`, JSON `{}` без заголовка Origin. Он находит сохранённые пользовательские настройки в D1, проверяет `manual/daily/weekly`, дату последней попытки и блокировку обновления. С `manual` ничего не делает. Для daily интервал 24 часа, weekly — 7 суток. Поддерживаются до 12 включённых источников. Proshoper читается прямым адаптером; при ошибке возможен резервный HTML scrape через сохранённый ключ Firecrawl. Для других страниц Firecrawl извлекает до 100 видимых карточек, включая неполные; Gemini опционально извлекает записи. Секреты расшифровываются внутри Worker, cloud-задаче они не передаются.

Отдельно хранятся исходные карточки `listings` и пригодные для меню `offers`. Прямой адаптер проверяет город в содержимом, даты в родительской кампании, цену/массу из явных полей; безопасно сопоставленные продукты автоматически получают проверку городского каталога. Изменения цены/массы/наличия сохраняются в истории (до 8 наблюдений). Исчезнувшая карточка становится `unknown`, а её автоматическая цена исключается из меню. Ошибка источника сохраняет предыдущие данные и не выдаётся за отсутствие товара. Ручное исправление помечается `verification:user` и защищено от автоматической перезаписи. Неполные карточки видны, но не подменяются выдуманными КБЖУ или массой. `listed` означает только присутствие в каталоге, а не складской остаток.

Первичный backfill от подключённого Firecrawl выполняется через `POST /api/catalog-service` с `operation:upsert`, пакетами до 150 карточек/100 цен; `inspect` возвращает только счётчики и статусы источников. Та же private boundary, выключатель `PRIVATE_REFRESH_ENABLED`, запрет Origin; запись разрешена лишь при ровно одном пользовательском пространстве в D1. Ключи, идентичности и история меню не возвращаются. Этот путь не зависит от наличия Firecrawl API key внутри приложения.

КБЖУ можно сверить по настоящему GTIN через Open Food Facts v3.6 (`nutrition`, не устаревшие пустые `nutriments`). Проверяются контрольная сумма, точный код, `per:100g`, `preparation:as_sold`, единицы и полнота. Оценочные источники остаются оценочными. Результаты кэшируются на 7 суток, глобальный лимит 1 обращение в 5 секунд. Совпадение показывается пользователю перед применением. Две точные фасовки Простоквашино сопоставлены отдельно с проверенными страницами производителя; дата происхождения КБЖУ сохраняется независимо от даты цены.

После фактического создания расписания тот же writer можно вызвать с `{ "scheduleInstalled": true }`, чтобы сохранить подтверждение установки для интерфейса. Это не подмена `get_site.automations`: создание и включённое состояние расписания проверяются нативным инструментом.

Регулярная задача должна молчать при обычном успешном/пропущенном выполнении. Сообщает о новых кандидатах на проверку, новой существенной ошибке источника или необходимом действии владельца. Не перепубликует сайт и не пишет в источники магазинов. Если platform service credential или исходные API недоступны, сообщает это явно; не обходить защиту.
