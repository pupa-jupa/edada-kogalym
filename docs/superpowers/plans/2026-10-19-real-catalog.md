# Реальные цены и автоматический сбор

Пользователь просит наполнить опубликованное приложение через подключённый Firecrawl, удалить демо и расширить сети. Дополнения: показывать все карточки даже без дат/фасовки, автоматизировать обновление, сохранять источники и изменения; обогащать КБЖУ специализированными базами.

1. Собрать городские каталоги Пятёрочки/Магнита и проверить Монетку/Перекрёсток. Отдельно зафиксировать реальные цены, сроки, единицы и доказательства города.
2. Удалить синтетический каталог из runtime и мигрировать пользовательское состояние без потери реальных записей. Отвергать явные demo-импорты.
3. Разделить исходные карточки и цены для расчёта. Неполные карточки сохранять; цену, единицу и наличие не додумывать. Поддержать истории изменений и обнаружение пропавших карточек.
4. Добавить прямой детерминированный Proshoper-адаптер, Firecrawl fallback и общий слой сырых карточек для прочих источников. Сохранять пользовательские коррекции.
5. Добавить независимое происхождение КБЖУ, точные производителя-совпадения, проверяемый поиск Open Food Facts по GTIN с кэшем/лимитом. Не переносить данные другой жирности или приготовленного продукта на сырой ингредиент.
6. Проверить алгоритм на реальных полных упаковках, миграцию, даты, неполные наблюдения, изменение цены, отсутствие карточки и внешнюю схему питания. Провести независимое review.
7. Проверить TypeScript, API/D1 и production build. Опубликовать точный commit в существующий owner-private Site, загрузить данные, прочитать счётчики обратно, проверить фактический server refresh и меню в браузере. Использовать имеющееся ежедневное расписание с настройкой daily; новую дублирующую задачу не создавать.

Границы: городской акционный каталог не равен полному ассортименту и складским остаткам конкретной точки. Внешние защищённые базы GS1/Национального каталога требуют отдельного доступа; неподдерживаемые API не выдумывать. Справочник ограничивает расчёт, но не видимость исходных карточек.
