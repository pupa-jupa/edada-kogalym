# ЕдаДа Implementation Plan

> For agentic workers: use subagent-driven-development for the independent optimizer task; implement the integrated server/UI in the owning session. Steps use checkbox syntax.

**Goal:** Опубликованное закрытое приложение для меню и покупок по бюджету и КБЖУ в Когалыме.
**Architecture:** React/Vinext frontend, pure TypeScript domain/optimizer, authenticated API and D1 persistence. External recipe generation and price ingestion are server-only and validated.
**Tech Stack:** Vinext, React 19, TypeScript, Zod, Drizzle/D1, Sites.
**Spec:** docs/superpowers/specs/2026-10-19-edada-design.md

## Global Constraints

- Russian UI. Budget covers whole packages, nutrition covers raw edible amounts.
- Explicit demo mode, never treat demo prices as current Kogalym prices.
- Reject expired/unconfirmed prices. Stage crawl results for review.
- Gemini IDs: gemini-3.8-flash and gemini-3.5-flash-lite; model editable.
- No secrets in source, frontend responses, logs or manifest.
- User-owned data is scoped by stable ChatGPT identity.

### Task 1: Domain and calculation

Files: lib/domain.ts, lib/catalog.ts, lib/optimizer.ts, tests/optimizer.test.ts.
Interface: optimizeMenu(input: PlanInput, offers: Offer[], recipes: Recipe[], now?: Date): PlanResult; see lib/domain.ts for the exact types.

- [ ] Write meaningful failing tests for package rounding, budget, protein tolerance, exclusion and infeasibility with `node --experimental-strip-types --test tests/optimizer.test.ts`.
- [ ] Implement bounded deterministic search over distinct recipes and portion variants. Purchase ingredients from selected eligible offers, share packages across meals, return explicit failure and deficit when constraints cannot be met. No claim of global optimality.
- [ ] Run tests and review spec/quality independently.

### Task 2: Persistence and integrations

Files: db/schema.ts, lib/server/*, app/api/*, tests/validation.test.ts.
Consumes the domain types. Produces GET bootstrap and POST settings/offers/import/sources/refresh/plan/history handlers.

- [ ] Add schema-owned tables for user state and refresh lease, generate D1 migration.
- [ ] Test invalid imports, dates, secret roundtrip and AI ingredient validation before implementation.
- [ ] Implement schema validation, encrypted key storage, persisted prices/history, Firecrawl staging and Gemini recipes. Requests require signed-in identity; service refresh only owner-private and server token. Reject cross-origin mutations.
- [ ] Verify API persistence, missing-key errors and source/refresh failure statuses.

### Task 3: Complete responsive UI

Files: app/page.tsx, app/food-app.tsx, app/components/*, app/globals.css, app/layout.tsx, public/favicon.svg.
Consumes authenticated API and PlanResult. Includes targets, ingredients exclusions, store selection, demo/real modes, recipes with grams and steps, grouped shopping checklist, catalog search, manual/import forms, source review, settings and history.

- [ ] Build polished Russian screens with native inputs, visible labels/focus and status feedback.
- [ ] Persist user settings and plans, print/download shopping list, expose source evidence/age and package leftovers.
- [ ] Verify desktop/mobile browser flows and truthful empty/error states.

### Task 4: Publication and scheduled update readiness

Files: .openai/hosting.json, drizzle/*, README.md, docs/research.md, docs/refresh.md.

- [ ] Run TypeScript, domain/validation tests and production build. Apply migration to preview and verify readback.
