# Обогащение реального каталога

Цены, даты и наличие остаются из Когалыма. Другие сайты дают только идентичность товара, массу и КБЖУ. В первой версии было 23 типа еды и 15 рецептов: отсутствие штрихкода или КБЖУ не было единственной причиной отсева. Теперь точные совпадения получают отдельные `e-` ингредиенты и кулинарную роль. Рецепты и Gemini используют общий реестр и только действующие местные предложения.

## Автоматический путь

Open Food Facts Search-a-licious ищется по названию с AND; найденный код проверяется контрольной суммой и актуальным API v3.6. Чтение продукта разделяет общий ограничитель с ручным barcode lookup. При серверном ключе Firecrawl используется поиск и live markdown карточки производителя/сети. Значения читаются из основного блока «на 100 г», с полной четвёркой нутриентов, до рекомендаций. Литры/штуки не превращаются в граммы. Блоки приготовленного продукта и неполные значения отклоняются. Кэш: совпадения 30 суток, отрицательный результат 7 суток, транспортные ошибки 1 час. После добавления Firecrawl key отрицательные проверки возвращаются в очередь.

Партия ограничена 6 продуктами и 85 секундами; запись происходит после каждого продукта. Название, фасовка, жирность, вкус и обработка должны совпадать. Кэш привязан к нормализованному имени и структуре фасовки, а не только URL. Изменённые/исчезнувшие местные карточки исключают автоматические цены; ручные правки защищены. `provider` разделяет результаты OFF и поиска по сайтам, чтобы OFF-only miss не блокировал подключённый Firecrawl.

## Фоновая работа через подключённый Firecrawl

Приложение остаётся owner-private. У облачной задачи нет API-ключей пользователя. Доступ к private updater получается нативным `get_site` для текущего проекта, токен только в памяти, заголовок `OAI-Sites-Authorization` и только для возвращённого Site origin. Не добавлять Origin. Не выводить и не записывать токен. Сервис не зависит от браузерного входа; native Firecrawl источники читаются отдельно через подключение владельца. При недоступности подключения работа останавливается с явной ошибкой, без фиктивных данных.

`POST /api/enrichment-service`:

- `{"operation":"pending","limit":6}` отдаёт только публичные товарные данные и ключи очереди. Выключенная пользователем автоматика возвращает пустой список. OFF-only misses доступны для веб-поиска; проверенные веб-совпадения/пропуски учитывают кэш.
- Для каждого товара — Firecrawl search по названию, бренду и фасовке, затем scrape найденной детальной страницы `maxAge:0`, markdown, HTTP200 и содержательный блок товара. Предпочтительны производители и официальные карточки сетей. Не читать КБЖУ из поисковых snippets или похожих товаров. Масса только явная; полное КБЖУ на 100 г as sold, без расчёта пропущенных нулей/ккал. GTIN необязателен; внутренние product IDs не GTIN.
- `{"operation":"import","checkedKeys":["<ключи проверенных товаров>"],"candidates":[...]}`. Candidate: `productName` из основного заголовка (можно дополнить явно опубликованным сортом из характеристик), `brand?`, `packGrams?`, `quantityText?`, `macros:{kcal,protein,fat,carbs}`, `sourceUrl`, `nutritionSourceUrl`, `quantitySourceUrl?`, `observedAt` ISO8601, `estimated:false`, `evidence` с фактическими цитатами (до2000символов). Ни цен, ни сроков/остатков другого города. `barcode` только явный опубликованный валидный GTIN. Сервер заново проверяет сопоставление; непринятые checkedKeys получают отрицательный кэш. После ошибки чтения товар не включать в checkedKeys, чтобы не объявлять его проверенным.
- `{"operation":"inspect"}` читает счётчики, состояния, причины, наличие серверного Firecrawl key, без секретов/личности/истории.
- `{"operation":"run","limit":6}` запускает server OFF/Firecrawl партию; `scheduleInstalled:true` отмечает фактическую установку отдельного расписания обогащения.

Проверить сохранённые совпадения через inspect и меню в интерфейсе. Плановый обход цен остаётся ежедневным в09:00, отдельная очередь КБЖУ выполняется каждый час. Обычные успехи не требуют уведомления владельца. Сообщать о существенной новой ошибке или требуемом подключении.

## Проверенные источники и пределы

- [OFF search OpenAPI](https://search.openfoodfacts.org/docs), [текущий OFF API](https://openfoodfacts.github.io/openfoodfacts-server/api/).
- [Firecrawl search](https://docs.firecrawl.dev/api-reference/endpoint/search), [rate limits](https://docs.firecrawl.dev/rate-limits).
- Увелка, Магнит и АктиБио дали живые примеры. GS1 массовый доступ и Национальный каталог требуют отдельного доступа; неподтверждённые endpoints не используются.
- Сопоставление намеренно оставляет неизвестными неоднозначные варианты. Кулинарные роли пока не покрывают всю еду; сырьё с костями, плотность жидкостей и съедобный выход не угадываются. Это видно в диагностике каталога.
